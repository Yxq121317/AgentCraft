## 我在做什么

我深耕大模型（LLM）应用开发，主要方向是 **AI 工作流编排**与**后端业务落地**。

写代码之前，我习惯先问三个问题：这个能力的不确定性在哪里？失败时用户会看到什么？我怎么证明它比上周更好？比起「又接了一个模型」，我更关心一个功能能不能被普通用户稳定地用起来。

## 我的工程方法：Vibe Coding 的正确打开方式

我大量使用 AI 辅助编程（Vibe Coding），但不认为它是「把需求丢给 AI 等结果」。我的实践方式是：

1. **先写规格，再要代码。** 把输入、输出、失败路径、验收标准写清楚，AI 生成的骨架才有讨论价值。
2. **小步生成，人工审阅。** 一次只让 AI 改一个模块，先跑测试与构建，再决定是否合并。
3. **用评测代替感觉。** Prompt 或流程有改动，必须跑一遍 bad case 集，看准确率、复核率、成本这些指标，而不是只看一个漂亮截图。
4. **人守住三件事：** 架构边界、异常兜底、产品取舍。这三件事目前 AI 替不了，也不该替。

这样做下来，AI 帮我省掉了大量样板代码和查文档的时间，让我能把精力放在设计、调试与「值不值得做」的判断上。
